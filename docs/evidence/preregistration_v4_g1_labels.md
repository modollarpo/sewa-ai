# Pre-registration v4-G1 - how the returned report-negation labels will be analysed

**FEASIBILITY ON PUBLIC DATA. NOT CLINICAL EVIDENCE.**

Status: **FROZEN before any label exists.** This document fixes (i) the extractor-v1 to
3-category mapping rule and (ii) the handling of `ambiguous` labels, *before* any human
label is seen. The rule and the ambiguity scenarios MUST NOT be changed after the labels
arrive. Any later change is "post-hoc, exploratory" and must be labelled as such.

Prior studies are frozen and not rewritten: `study-v1-frozen`, `study-v3-frozen`; the v4
primary result in `docs/evidence/feasibility_report_v4.md` is unchanged.

---

## 0. What is being labelled

G1/G1b are the report-negation runs: 150 generated reports for prompt variant **a** (G1)
and 150 for variant **b** (G1b), 50 scans x 3 reports each, generated by a small text-only
1.5B model (`Qwen2.5-1.5B-Instruct`, Q4_K_M). Each report is labelled against the
classifier's operating decision for that scan (`positive` iff calibrated `p >= 0.5`):

- `consistent`  - the report agrees with / does not contradict the decision;
- `contradicts` - the report asserts the OPPOSITE of the decision (a true contradiction);
- `ambiguous`   - cannot be adjudicated; includes a report that both asserts and denies
  the finding (instruction: *"If a report both asserts and denies the finding, label it
  ambiguous and add a note."*).

Labelling artefacts (unlabelled, hashed in `docs/evidence/label_hashes.txt`):
`validation/labelling/blessing_labelling_sheet.xlsx` (all 300, variant-blind),
`validation/labelling/dolapo_subset_sheet.xlsx` (the 50-row second-labeller subset),
`validation/labelling/clinician_review_sheet.xlsx` (120 extractor sentences, 5-class).

**Labellers.** The two labellers of the 300 reports are the **co-founder and the founder**
of the project - they are **not independent** of the project, and their clinical
qualifications are **unverified** unless separately stated. The sample is **small**
(50 scans). This is a feasibility exercise on public data, **not a clinical result**.

## 1. Extractor-v1 -> 3-category mapping rule (FIXED)

The v1 extractor emits a polarity in {present, absent, uncertain, historical, resolved}.
To compare it with the three manual categories, the following rule is fixed now:

| extractor v1 | condition | mapped category |
|---|---|---|
| `uncertain` | - | `ambiguous` |
| `historical` / `resolved` | - | `consistent` |
| `present` | `decision = present` | `consistent` |
| `present` | `decision = absent` | `contradicts` |
| `absent` | `decision = absent` | `consistent` |
| `absent` | `decision = present` | `contradicts` |

Rationale for `historical`/`resolved` -> `consistent`: a past or resolved mention does not
assert the opposite of the current triage decision, so it is not a contradiction.

This rule is implemented once in `validation/scripts/v4_merged_label_analysis.py`
(`map_v1`) and is **not** to be retuned.

---

## 2. Ambiguity handling (FIXED, two scenarios)

- **Primary manual rate** (the headline): `ambiguous` labels are **excluded** from the
  denominator; the rate is `contradicts / (consistent + contradicts)`. The number of
  ambiguous labels is always reported alongside.
- **Extractor comparison (binary).** Because the extractor produces no `ambiguous`
  *manual* companion, two scenarios are reported, fixed now:
  1. **ambiguous counted as `contradicts`** (optimistic for the extractor's "unsafe" class);
  2. **ambiguous counted as `consistent`** (conservative).
  For each scenario the binary confusion matrix (manual positives = `contradicts`) and the
  accuracy are reported. The 3x3 confusion matrix and the exact 3-class accuracy are also
  reported, treating `ambiguous` as its own category.
- **Decision routing.** `uncertain` maps to `ambiguous` (scenario-independent); the two
  scenarios only affect how *manual* `ambiguous` rows are scored against extractor-binary.

---

## 3. Metrics and their uncertainty (FIXED)

- **Inter-labeller agreement (item 7):** Cohen's kappa between the primary labeller
  (Blessing) and the second labeller (Dolapo) on the 50-row subset, over the 3 categories
  including `ambiguous`, with a **scan-cluster bootstrap 95% CI** (resampling the
  `StudyInstanceUID` clusters, seed 20261014, 5000 resamples) and the list of
  disagreements. The subset is labelled by both people; the full 300 by one.
- **Extractor vs manual (item 8):** 3x3 confusion (manual rows x extractor cols), exact
  3-class accuracy, and the two binary ambiguity scenarios above.
- **True contradiction rate (items 9, 11):** the manual `contradicts` rate with a
  **scan-cluster bootstrap 95% CI** (resampling the 50 scans), computed **per prompt
  variant** (a = G1, b = G1b) and additionally **split by classifier decision**
  (present / absent). This manual rate is the headline of the G1 report. The extractor
  "contradiction rate" is reported only as the UNVALIDATED upper bound.

---

## 4. Anti-tuning and integrity

- The mapping rule and ambiguity handling above were fixed before any label was seen.
- No report text is used to tune the extractor; the extractor v2 (separate
  pre-registration) is developed only on a synthetic probability set, never on the 300.
- Returned files are checked against the hashed originals before analysis: same rows,
  same ids, same immutable columns; only label columns may be filled; label values must be
  from the allowed set. On any mismatch, analysis stops.

---

## 5. Known limitations (restated in the report)

Small sample (50 scans); labellers not independent and clinical qualifications unverified;
text-only 1.5B generator (no image conditioning), a deviation from the filed design; no
real patient text; RSNA-derived artefacts are research-only. **Feasibility on public data,
not clinical evidence.**
